# 输出与调试

输出与调试（对应 GaussDB DBE_OUTPUT、DBE_PROFILER）。

---

## DBMS_OUTPUT

**包用途**：从存储过程、包、触发器发送消息，特别适合显示 PL/SQL 调试信息。PUT/PUT_LINE 向缓冲区写信息，GET_LINE/GET_LINES 读出；包禁用时所有调用被忽略。

| Subprogram | 说明 |
|---|---|
| DISABLE | 禁用消息输出 |
| ENABLE | 启用消息输出 |
| GET_LINE | 从缓冲区取一行 |
| GET_LINES | 从缓冲区取一组行 |
| NEW_LINE | 结束 PUT 创建的行 |
| PUT | 向缓冲区写部分行 |
| PUT_LINE | 向缓冲区写整行 |

## DBMS_PROFILER

**包用途**：收集 PL/SQL 应用的剖析（性能）数据，用于性能改进或代码覆盖率。在 PL/SQL 虚拟机层收集每行执行次数、耗时等，存入数据库表供查询。

| Subprogram | 说明 |
|---|---|
| FLUSH_DATA | 刷新用户会话收集的剖析数据 |
| GET_VERSION | 获取本 API 版本 |
| INTERNAL_VERSION_CHECK | 校验本包版本与数据库实现兼容 |
| PAUSE_PROFILER | 暂停剖析数据收集 |
| RESUME_PROFILER | 恢复剖析数据收集 |
| START_PROFILER | 在用户会话开始剖析数据收集 |
| STOP_PROFILER | 停止剖析数据收集 |

### DBMS_OUTPUT 概述
该包通常用于调试，或用于向 SQL*DBA 或 SQL*Plus 显示消息和报告（例如，通过对过程应用 SQL 命令 `DESCRIBE` 所产生的输出）。
此包中的 PUT Procedure 和 PUT_LINE Procedure 使您能够将信息放入缓冲区，供另一个触发器、过程或包读取。在单独的 PL/SQL 过程或匿名块中，您可以通过调用 GET_LINE Procedure 和 GET_LINES Procedure 来显示缓冲的信息。
如果禁用了该包，则对子程序的所有调用都将被忽略。这样，您可以设计您的应用程序，使得子程序仅在客户端能够处理信息时才可用。
### DBMS_OUTPUT 安全模型
`dbmsotpt.sql` 脚本必须以 `SYS` 用户身份运行。这将创建公共同义词 `DBMS_OUTPUT`，并将此包的 `EXECUTE` 权限授予 `public`。
### DBMS_OUTPUT 操作说明
以下操作说明适用于 DBMS_OUTPUT。
- 如果您不调用 GET_LINE，或者您没有在 SQL*Plus 屏幕上显示消息，则缓冲的消息将被忽略。
- SQL*Plus 在发出 SQL 语句或匿名 PL/SQL 调用之后调用 GET_LINES。
``````
```
DBMS_OUTPUT.ENABLE (buffer_size => NULL);
```
- 在 SQL*Plus 中键入 SET SERVEROUTPUT ON 具有调用且不限制输出的效果。
- 您通常应避免让应用程序代码调用 DISABLE Procedure 或 ENABLE Procedure，因为这可能会破坏像 SQL*Plus 这样的外部工具控制是否显示输出的尝试。
注意：
使用 `DBMS_OUTPUT` 发送的消息直到发送子程序或触发器完成后才会实际发送。在过程执行期间没有刷新输出的机制。
### DBMS_OUTPUT 异常
`DBMS_OUTPUT` 子程序引发应用程序错误 `ORA-20000` 并返回错误。
输出过程可能返回以下错误：

|---|---|
| ORU-10027: | 缓冲区溢出 |
| ORU-10028: | 行长度溢出 |
### DBMS_OUTPUT 规则与限制
以下是对 DBMS_OUTPUT 行和缓冲区大小的限制。
- 最大行大小为 32767 字节。
- 默认缓冲区大小为 20000 字节。最小大小为 2000 字节，最大为无限。
### DBMS_OUTPUT 示例
本主题包含三个使用 DBMS_OUTPUT 的示例。
示例 1：使用触发器产生输出
您可以使用触发器来打印调试过程中的一些输出。例如，您可以编写触发器代码来调用：
```
DBMS_OUTPUT.PUT_LINE('I got here:'||:new.col||' is the new value');
```
如果您已启用 `DBMS_OUTPUT` 包，则此 `PUT_LINE` 生成的文本将被缓冲，并且您可以在执行语句（推测是导致触发器触发的某些 `INSERT`、`DELETE` 或 `UPDATE`）之后检索该行信息。例如：
```
BEGIN
   DBMS_OUTPUT.GET_LINE(:buffer, :status);
END;
```
然后您可以选择在屏幕上显示缓冲区。您重复调用 `GET_LINE` 直到 `status` 返回非零值。为了获得更好的性能，您应该使用对 GET_LINES Procedure 的调用，它可以返回行数组。
示例 2：调试存储过程和触发器
`DBMS_OUTPUT` 包通常用于调试存储过程和触发器。该包也可用于使您能够检索有关对象的信息并格式化此输出，如“示例 3：检索有关对象的信息”中所示。
此函数查询 employee 表并返回指定部门的总薪水。该函数包含对 `PUT_LINE` 过程的几次调用：
```
CREATE FUNCTION dept_salary (dnum NUMBER) RETURN NUMBER IS
   CURSOR emp_cursor IS
      SELECT sal, comm FROM emp WHERE deptno = dnum;
   total_wages    NUMBER(11, 2) := 0;
   counter        NUMBER(10) := 1;
BEGIN
   FOR emp_record IN emp_cursor LOOP
      emp_record.comm := NVL(emp_record.comm, 0);
      total_wages := total_wages + emp_record.sal
         + emp_record.comm;
      DBMS_OUTPUT.PUT_LINE('Loop number = ' || counter ||
         '; Wages = '|| TO_CHAR(total_wages));  /* Debug line */
      counter := counter + 1; /* Increment debug counter */
   END LOOP;
   /* Debug line */
   DBMS_OUTPUT.PUT_LINE('Total wages = ' ||
     TO_CHAR(total_wages));
   RETURN total_wages;
END dept_salary;
```
假设 `EMP` 表包含以下行：
```
EMPNO          SAL     COMM     DEPT
-----        ------- -------- -------
1002           1500      500      20
1203           1000               30
1289           1000               10
1347           1000      250      20
```
假设用户在 SQL*Plus 中执行以下语句：
```
SET SERVEROUTPUT ON
VARIABLE salary NUMBER;
EXECUTE :salary := dept_salary(20);
```
然后用户将在输出窗格中看到显示的以下信息：
```
Loop number = 1; Wages = 2000
Loop number = 2; Wages = 3250
Total wages = 3250
PL/SQL procedure successfully executed.
```
示例 3：检索有关对象的信息
在此示例中，用户使用了 `EXPLAIN` `PLAN` 命令检索有关语句执行计划的信息，并将其存储在 `PLAN_TABLE` 中。用户还为此语句分配了语句 ID。`EXPLAIN_OUT` 过程从此表中检索信息，并以嵌套方式格式化输出，更贴近地描绘了处理 SQL 语句所经历的步骤顺序。
```
 /****************************************************************/
/* Create EXPLAIN_OUT procedure. User must pass STATEMENT_ID to */
/* to procedure, to uniquely identify statement.                */
/****************************************************************/
CREATE OR REPLACE PROCEDURE explain_out
   (statement_id IN VARCHAR2) AS
   -- Retrieve information from PLAN_TABLE into cursor EXPLAIN_ROWS.
   CURSOR explain_rows IS
      SELECT level, id, position, operation, options,
         object_name
      FROM plan_table
      WHERE statement_id = explain_out.statement_id
      CONNECT BY PRIOR id = parent_id
         AND statement_id = explain_out.statement_id
      START WITH id = 0
       ORDER BY id;
BEGIN
   -- Loop through information retrieved from PLAN_TABLE:
   FOR line IN explain_rows LOOP
      -- At start of output, include heading with estimated cost.
      IF line.id = 0 THEN
         DBMS_OUTPUT.PUT_LINE ('Plan for statement '
            || statement_id
            || ', estimated cost = ' || line.position);
      END IF;
      -- Output formatted information. LEVEL determines indention level.
      DBMS_OUTPUT.PUT_LINE (lpad(' ',2*(line.level-1)) ||
         line.operation || ' ' || line.options || ' ' ||
         line.object_name);
   END LOOP;
END;
```

#### DISABLE 过程

此过程禁用对 `PUT`、`PUT_LINE`、`NEW_LINE`、`GET_LINE` 和 `GET_LINES` 的调用，并清除缓冲区中的任何剩余信息。
与 ENABLE 过程一样，如果您使用 SQL*Plus 的 `SERVEROUTPUT` 选项，则无需调用此过程。
语法
```
DBMS_OUTPUT.DISABLE;
```
Pragma
```
pragma restrict_references(disable,WNDS,RNDS);
```

#### ENABLE 过程

此过程允许调用 `PUT`、`PUT_LINE`、`NEW_LINE`、`GET_LINE` 和 `GET_LINES`。
如果 `DBMS_OUTPUT` 包未激活，对这些过程的调用将被忽略。
语法
```
DBMS_OUTPUT.ENABLE (
   buffer_size IN INTEGER DEFAULT 20000);
```
Pragma
```
pragma restrict_references(enable,WNDS,RNDS);
```
参数
Table 128-3 ENABLE 过程参数
| Parameter | Description |
|---|---|
| buffer_size | 缓冲信息量的上限（以字节为单位）。将 buffer_size 设置为 NULL 表示无限制。 |
使用说明
````
- 使用 SQL*Plus 的 SET SERVEROUTPUT 选项时，无需调用此过程。
``````````
- 如果多次调用 ENABLE，则 buffer_size 为最后指定的值。当用户指定 buffer_size（NOT NULL）时，最大大小为 1,000,000，最小为 2,000。
- NULL 预期为常规选择。默认值为 20,000，这是为了向后兼容不支持无限制缓冲的早期数据库版本。

参数
表 128-4 GET_LINE 过程参数
| Parameter | Description |
|---|---|
| line | 返回单行缓冲信息，不包含最后的换行符。您应将此参数的 actual 声明为 VARCHAR2 (32767)，以避免出现 "ORA-06502: PL/SQL: numeric or value error: character string buffer too small" 的风险。 |

````

``````

``````````
- 在调用 GET_LINE 或 GET_LINES 之后，下次调用 PUT、PUT_LINE 或 NEW_LINE 之前未检索到的所有行都会被丢弃，以避免它们与下一条消息混淆。

## DBMS_PROFILER
该包提供了一个接口，用于分析现有的 PL/SQL 应用程序并识别性能瓶颈。然后，您可以收集并持久化存储 PL/SQL 分析数据。

### DBMS_PROFILER 概述
该包支持收集分析器（性能）数据，以提升性能或确定 PL/SQL 应用程序的代码覆盖率。应用程序开发者可以利用代码覆盖率数据来集中精力进行增量测试。
通过此接口，您可以生成会话中执行的所有命名库单元的分析信息。分析器在 PL/SQL 虚拟机级别收集信息。这些信息包括每行执行的总次数、执行该行所花费的总时间，以及在特定一次执行中该行所花费的最短和最长时间。
注：
可以推断已收集数据的 PL/SQL 单元的代码覆盖率数据。
分析信息存储在数据库表中。这允许对数据进行查询：您可以构建自定义报告（摘要报告、最热行、代码覆盖率数据等），并分析数据。

### DBMS_PROFILER 安全模型
分析器仅为用户拥有 `CREATE` 权限的单元收集数据；您不能使用该包来分析仅被授予 `EXECUTE ONLY` 访问权限的单元。通常，如果用户可以调试某个单元，那么该用户也可以分析它。但是，无论单元是否编译为 `DEBUG.` 都可以对其进行性能分析。Oracle 建议正在被分析的模块应编译为 `DEBUG,` 因为这会在数据库中提供关于该单元的额外信息。
注：
`DBMS_PROFILER` 将任何以 `NATIVE` 模式编译的程序单元视为您没有 `CREATE` 权限的情况，也就是说，您不会得到任何输出。
### DBMS_PROFILER 操作说明
这些说明描述了典型的运行、如何解释输出以及两种异常生成方法。
典型运行
提升应用程序性能是一个迭代过程。每次迭代包含以下步骤：
- 在启用分析器数据收集的情况下，使用一个或多个基准测试运行应用程序。
- 分析分析器数据并识别性能问题。
- 修复问题。
PL/SQL 分析器使用“运行”的概念来支持此过程。一次运行涉及在启用分析器数据收集的情况下通过基准测试运行应用程序。您可以通过调用 `START_PROFILER` 和 `STOP_PROFILER` 函数来控制运行的开始和结束。
用户必须首先在分析器用户的模式中创建数据库表以收集数据。`PROFTAB`.`SQL` 脚本创建持久化存储分析器数据所需的表和其他数据结构。
请注意，运行 `PROFTAB.SQL` 会删除当前表。`PROFTAB.SQL `脚本位于 `RDBMS/ADMIN` 目录中。某些 PL/SQL 操作（如首次执行 PL/SQL 单元）可能涉及对目录表的 I/O 操作，以加载正在执行的 PL/SQL 单元的字节码。此外，首次调用包过程或函数时，执行包初始化代码可能需要一些时间。
为避免计入此开销，在收集分析数据之前“预热”数据库。为此，在不收集分析器数据的情况下运行一次应用程序。
您可以允许对系统上的所有用户进行性能分析，例如，分析包的所有用户，而不管是谁在使用它。在这种情况下，`SYSADMIN` 应使用修改后的 `PROFTAB.SQL` 脚本，该脚本：
- 创建分析器表和序列
``````
- 向所有用户授予对这些表和序列的 SELECT/INSERT/UPDATE 权限
- 为表和序列定义公共同义词 注：请勿更改表的实际字段。
因此，典型的运行涉及：
- 在运行中启动分析器数据收集。
- 执行需要分析器和代码覆盖率数据的 PL/SQL 代码。
````
- 停止分析器数据收集，将本次运行收集的数据写入数据库表 注：当用户断开连接时，收集的分析器数据不会自动存储。您必须显式调用 FLUSH_DATA 或 STOP_PROFILER 函数才能在会话结束时存储数据。停止数据收集会存储已收集的数据。
随着应用程序的执行，分析器数据会收集在内存数据结构中，这些结构在运行期间持续存在。您可以在运行期间的中间点调用 `FLUSH_DATA` 函数以获取增量数据并释放分配的分析器数据结构的内存。刷新收集的数据涉及将收集的数据存储在先前创建的数据库表中。
另请参阅：
"FLUSH_DATA Function and Procedure"。
解释输出
表 `plsql_profiler_data` 为生成了代码的源单元的每一行包含一行。line# 值指定源行。如果该行存在，并且该行中的 total_occur 值 > 0，则表示执行了与该行关联的一些代码。如果该行存在，并且 total_occur 值为 0，则表示未执行与该行关联的任何代码。如果表中不存在该行，则表示没有为该行生成代码，因此不应在报告中提及它
如果单个语句的源位于单行上，则为该语句生成的任何代码都将归属于该行号。（在某些情况下，例如简单的声明，或者由于优化，不需要代码）。要获取覆盖率信息，应使用 `PLSQL_OPTIMIZE_LEVEL=1` 编译单元。
如果一个语句跨越多行，则为该语句生成的任何代码都将归属于该范围内的某一行，但不能保证该范围内的每一行都会有归属于它的代码。在这种情况下，line# 值集合中会出现空隙。特别是，多行 SQL 相关语句可能看起来位于单行（通常是第一行）上。这是因为 PL/SQL 将游标的已处理文本传递给 SQL 引擎；因此，就 PL/SQL 而言，整个 SQL 语句是一个单一的不可分割的操作。
当多个语句位于同一行时，分析器将合并每个语句的出现次数。如果某一行包含嵌入的控制流，这可能会造成混淆。例如，如果 `'then ...'` 和` 'else ...' `在同一行上，则无法确定执行的是 `'then'` 还是 `'else'`。
通常，如果每个语句都单独占一行，则最容易解释分析器和覆盖率报告。
两种异常生成方法
此包中的每个例程都有两个版本，允许您决定如何报告错误。
- 一个函数以状态值返回成功/失败，且永远不会引发异常
- 一个过程在成功时正常返回，在失败时引发异常
在这两种情况下，函数和过程的参数都是相同的。只是错误报告的方法不同。如果发生错误，函数返回的错误代码与过程引发的异常之间存在对应关系。
为避免冗余，以下部分仅提供有关函数形式的详细信息。
