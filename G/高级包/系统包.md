## PKG_SERVICE

PKG_SERVICE支持的接口请参见表1。

| 接口名称 | 描述 |
|---|---|
| PKG_SERVICE.SQL_IS_CONTEXT_ACTIVE | 确认该CONTEXT是否已注册。 |
| PKG_SERVICE.SQL_CLEAN_ALL_CONTEXTS | 取消所有注册的CONTEXT。 |
| PKG_SERVICE.SQL_REGISTER_CONTEXT | 注册一个CONTEXT。 |
| PKG_SERVICE.SQL_UNREGISTER_CONTEXT | 取消注册该CONTEXT。 |
| PKG_SERVICE.SQL_SET_SQL | 向CONTEXT设置一条SQL语句，目前只支持SELECT。 |
| PKG_SERVICE.SQL_RUN | 在一个CONTEXT上执行设置的SQL语句。 |
| PKG_SERVICE.SQL_NEXT_ROW | 读取该CONTEXT中的下一行数据。 |
| PKG_SERVICE.SQL_GET_VALUE | 读取该CONTEXT中动态定义的列值。 |
| PKG_SERVICE.SQL_SET_RESULT_TYPE | 根据类型OID动态定义该CONTEXT的一个列。 |
| PKG_SERVICE.JOB_CANCEL | 通过任务id来删除定时任务。 |
| PKG_SERVICE.JOB_FINISH | 禁用或者启用定时任务。 |
| PKG_SERVICE.JOB_SUBMIT | 提交一个定时任务。作业号由系统自动生成或由用户指定。 |
| PKG_SERVICE.JOB_UPDATE | 修改定时任务的属性，包括任务内容、下次执行时间、执行间隔。 |
| PKG_SERVICE.SUBMIT_ON_NODES | 提交一个任务到所有节点，作业号由系统自动生成。 |
| PKG_SERVICE.ISUBMIT_ON_NODES | 提交一个任务到所有节点，作业号由用户指定。 |
| PKG_SERVICE.SQL_GET_ARRAY_RESULT | 获取该CONTEXT中返回的数组值。 |
| PKG_SERVICE.SQL_GET_VARIABLE_RESULT | 获取该CONTEXT中返回的列值。 |

```
PKG_SERVICE.SQL_CLEAN_ALL_CONTEXTS(
)
RETURN VOID;
```
- PKG_SERVICE.SQL_CLEAN_ALL_CONTEXTS该函数用于取消所有CONTEXT。 PKG_SERVICE.SQL_CLEAN_ALL_CONTEXTS原型为：
```
DBE_SQL.REGISTER_CONTEXT(
)
RETURN INTEGER;
```
- PKG_SERVICE.SQL_REGISTER_CONTEXT该函数用于打开一个CONTEXT。打开CONTEXT是后续对该CONTEXT进行各项操作的前提。该函数无需传入任何参数，内部会自动递增生成CONTEXT id，并将其作为返回值赋给一个INTEGER类型的变量。 PKG_SERVICE.SQL_REGISTER_CONTEXT原型为：
```
PKG_SERVICE.SQL_UNREGISTER_CONTEXT(
 context_id     IN INTEGER
)
RETURN INTEGER;
```

| 参数名称 | 描述 |
|---|---|
| context_id | 计划关闭的CONTEXT id号。 |

- PKG_SERVICE.SQL_UNREGISTER_CONTEXT该函数用于关闭一个CONTEXT。关闭CONTEXT是该CONTEXT中各项操作的结束。如果在存储过程结束时未调用该函数，CONTEXT占用的内存将不会被释放，因此关闭CONTEXT非常重要。由于异常情况可能导致存储过程中途退出，从而导致CONTEXT未能关闭，建议存储过程中有异常处理，将该接口包含在内。 PKG_SERVICE.SQL_UNREGISTER_CONTEXT原型为：
```

- PKG_SERVICE.SQL_RUN该函数用于执行一个给定的CONTEXT。该函数接收一个CONTEXT id，运行后获得的数据用于后续操作。目前仅支持SELECT查询语句的执行。 PKG_SERVICE.SQL_RUN原型为：

```

| 参数 | 类型 | 入参/出参 | 是否可以为空 | 描述 |
|---|---|---|---|---|
| id | INTEGER | IN | 否 | 将要禁用或启用的定时任务的id。 |
| broken | BOOLEAN | IN | 否 | 状态标志位，true代表禁用，false代表启用。根据true或false值更新当前JOB的状态；如果为空值，则不改变原有JOB的状态。 |
| next_time | TIMESTAMP | IN | 是 | 下次运行时间，默认为当前系统时间。该参数可以省略，为默认值。 如果参数broken状态为true，则更新该参数为'4000-1-1'。如果参数broken状态为false，参数next_time不为空值时，更新指定JOB的next_time值；next_time为空值时，不更新next_time值。 |

- PKG_SERVICE.JOB_FINISH该函数用于禁用或者启用定时任务。 PKG_SERVICE.JOB_FINISH原型为：
```
PKG_SERVICE.JOB_SUBMIT(
id            IN   BIGINT,
content       IN   TEXT,
next_time     IN   TIMESTAMP DEFAULT sysdate,
interval_time IN   TEXT  DEFAULT 'null',
job           OUT  INTEGER);
```
  - 当创建一个定时任务（JOB）时，系统默认将当前数据库和用户名与当前创建的定时任务绑定起来。
  - 该接口函数可以通过CALL语句或SELECT语句调用，如果通过SELECT语句调用，可以不填写出参。如果在存储过程中，则需要通过PERFORM语句调用该接口函数。
  - 如果提交的SQL语句任务使用到非PUBLIC的schema，应该指定表或者函数的schema，或者在SQL语句前添加SET current_schema = xxx;语句。

| 参数 | 类型 | 入参/出参 | 是否可以为空 | 描述 |
|---|---|---|---|---|
| id | BIGINT | IN | 否 | 定时任务id。如果传入id为NULL，则内部会生成作业id。 |
| content | TEXT | IN | 否 | 要执行的SQL语句。支持一个或多个DML、匿名块、调用存储过程的语句或三种类型混合的场景。 |
| next_time | TIMESTAMP | IN | 否 | 下次作业运行时间。默认值为当前系统时间（sysdate）。如果是过去时间，在提交作业时表示立即执行。 |
| interval_time | TEXT | IN | 是 | 用来计算下次作业运行时间的时间表达式，可以是interval表达式，也可以是sysdate加上一个NUMERIC值（例如：sysdate+1.0/24）。如果为空值或字符串"null"，表示只执行一次，执行后，JOB状态STATUS变成'd' ，表示不再执行。 |
| job | INTEGER | OUT | 否 | 作业号。范围为1～3000000。当使用SELECT语句调用pkg_service.job_submit时，该参数可以省略。 |

## PKG_UTIL

PKG_UTIL支持的所有接口请参见表1：
PKG_UTIL包中的LOB修改接口（如LOB_WRITE_HUGE、LOB_COPY_HUGE、LOB_CONVERTTOBLOB、LOB_CONVERTTOBLOB_HUGE、LOADBLOBFROMFILE等）仅更新内存中的LOB变量，不会自动更新其关联的物理表数据。即使目标行已通过SELECT ... FOR UPDATE锁定，LOB数据变更也不会自动持久化到数据库表中。如需保存修改结果，必须显式执行UPDATE语句。
