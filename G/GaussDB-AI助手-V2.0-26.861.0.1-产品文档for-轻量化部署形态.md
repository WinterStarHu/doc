## 概述

GaussDB AI助手元数据库存储了知识库文档与服务运行的核心参数。为防止因硬件故障、人为错误或软件故障导致数据丢失或服务中断，必须建立有效的备份与恢复机制。本章节描述了元数据库的备份与恢复，确保在发生故障时能快速恢复业务，减少中断时间。
#### 场景说明
备份恢复任务的使用场景如下：
- 用于日常备份，确保系统及组件的数据安全。
- 当系统故障导致无法工作时，使用已备份的数据完成恢复操作。
#### 备份策略
GaussDB AI助手支持逻辑备份，逻辑备份是将GaussDB AI助手元数据库中数据备份并导出，生成SQL文件。
逻辑备份建议定期对GaussDB AI助手进行备份，备份周期为每周一次或每月一次即可。
#### 恢复策略与流程
GaussDB AI助手恢复步骤为：
- 安全停止微服务：依次停止运行中的微服务。
- 恢复元数据库：逻辑备份恢复时需清除当前元数据库上所有连接并删除元数据库，然后重新创建数据库并将SCHEMA权限依次赋给数据库，再导入备份元数据库时生成的SQL文件；物理备份恢复时直接执行对应恢复命令，导入数据文件。
- 安全启动微服务：依次启动微服务的镜像。

## 服务简介

GaussDB AI助手是一个数据库管理面智能运维系统，它极大程度地提高了用户的运维效率，以交互式的形式，解答用户对GaussDB功能相关的专业问题，对数据库运行现状和故障更新进行解答，以及为用户提供自建知识库的功能，实现新问题迭代。
该系统主要包括如下几个功能模块：
- 智能问答，提供与GaussDB相关的问题的专业解答
- 智能运维，提供基于大模型交互和思考能力结合的Agent实现问答交互式智能运维
- 知识库管理，提供了对业务相关的运维文档进行加载切分，以及向量化，构建自定义的知识库

## 部署架构

GaussDB AI助手服务部署节点分为服务节点集群（CPU）和模型推理节点集群（NPU/CPU）。服务节点集群包括Platform、GaussDB Doer DB和GaussMaster微服务，整体部署形态为主备从三节点；模型推理节点集群部署ModelService服务，部署形态为一主一备双节点，推荐使用NPU节点。
| 微服务 | 部署节点 | 说明 |
|---|---|---|
| Platform-Service | CPU | 提供GaussDB AI助手前端页面，以及GaussDB AI助手的鉴权、后台交互、接口代理 |
| GaussDB Doer DB | CPU | 元数据库，以及存储华为云数据库知识的向量知识库 |
| GaussMaster-Service | CPU | 数据库运维自动化诊断及恢复功能 |
| ModelService | CPU/NPU | 嵌入模型推理，重排模型推理，第三方大模型接口封装 |

## 网络端口要求

图1展现了GaussDB AI助手部署形态Platform节点和 ModelService节点各端的端口出入情况，标记的端口均为默认端口。实例节点之间等更详细的端口开通要求请查看对应版本的《GaussDB AI助手 通信矩阵(for 轻量化部署形态)》。
为避免端口冲突，发送端口范围需要设置在32768-60999，推荐包含的端口数量在20000以上，系统会在规划的端口范围中随机选择端口发送请求。

****
- 若端口范围不在32768-60999，可执行以下命令修改或新增系统参数配置。vi /etc/sysctl.conf 参照下图，找到配置项net.ipv4.ip_local_port_range，并修改值为32768 60999。若没有该配置项，请手动添加改配置项。
****
- 执行以下命令使配置生效。sysctl -p

## 修改安装配置文件

#### 操作场景
介绍如何配置安装所需的配置文件，配置参数详细说明见表1。
#### 操作步骤
****
- 以root用户登录待安装云数据库GaussDB管理平台（TPOPS）的节点。该节点为上传软件包所在节点。
****
- 执行以下命令，进入到配置文件所在目录。cd /data/docker-service/config/gaussdoer
****
- 执行以下命令，进入配置文件。vi user_edit_file.conf
```
[user_edit]
ssh_port = 22
gauss_path = /opt/gaussdb
GaussMaster_ip1 = 192.168.*.1
GaussMaster_ip2 = 192.168.*.2
GaussMaster_ip3 = 192.168.*.3
ModelService_ip1 = 192.168.*.1
ModelService_ip2 = 192.168.*.2
tpops_ip_list = 192.168.*.1,192.168.*.2,192.168.*.3
main_path = /opt/cloud
tpops_main_path = /opt/cloud
log_path = /opt/cloud/logs
docker_path = /opt/docker
[module_service]
gd_llm_url_key = https:
gd_llm_no_think_model_url_key =
gd_llm_auth_enable =
gd_llm_auth_api_token =
gd_llm_auth_customize_json =
gd_llm_device_type = npu
gd_llm_device_path = /dev/davinci0
gd_ms_uvicorn_worker =
gd_ms_cpu_core_num =
gd_ms_cpu_affinity =
gd_llm_max_gen_token =
gd_gm_safety_filter =
gd_gm_field_filter =
[gauss_master]
gd_llm_model_name =
gd_llm_no_think_model_name =
```
| 参数名称 | 是否必选 | 参数解释 | 约束限制 |
|---|---|---|---|
| ssh_port | 是 | 节点之间登录的SSH端口号，默认为22。 | - |
| gauss_path | 是 | 元数据库安装目录。 | 不能在/home目录下，配置的目录长度不超过64位，不允许出现中文路径。 |
| GaussMaster_ip1 | 是 | GaussMaster节点1本机IP地址。 | 需要配置为执行节点IP地址，执行节点IP地址为下发命令的节点的IP地址。配置的IP地址要在ifconfig查询的范围内，且仅支持IPv4地址。 |
| GaussMaster_ip2 | 否 | GaussMaster节点2本机IP地址。 | 三节点部署时必填。 需要配置成其他的实际节点IP地址。配置的IP地址要在ifconfig查询的范围内，且仅支持IPv4地址。单节点部署时等号右侧置空即可，不可删除参数。 |
| GaussMaster_ip3 | 否 | GaussMaster节点3本机IP地址。 | 三节点部署时必填。不填写时等号右侧置空即可，不可删除参数。 需要配置成其他的实际节点IP地址。配置的IP地址要在ifconfig查询的范围内，且仅支持IPv4地址。单节点部署时等号右侧置空即可，不可删除参数。 |
| tpops_ip_list | 是 | TPOPS安装节点IP列表。 | 如果为TPOPS为三节点部署，三个IP之间以英文逗号分隔。 |
| ModelService_ip1 | 是 | ModelService安装节点1。 | 配置的IP地址要在ifconfig查询的范围内，且仅支持IPv4地址。 |
| ModelService_ip2 | 否 | ModelService安装节点2。 | 不可删除参数。不填写时等号右侧置空即可，不可与ModelService_ip1相同。 |
| main_path | 是 | 微服务运行目录。 | 目录可自定义，仅支持自定义第一级目录，二级目录cloud不允许修改。配置的目录长度不超过64位，不允许出现中文路径。 |
| tpops_main_path | 是 | tpops所在节点的微服务运行目录。 | TPOPS所在节点的运行目录，需要从TPOPS节点的安装配置目录中查看。 |
| log_path | 是 | 日志目录。 | 目录可自定义，仅支持自定义第一级目录，二级目录cloud及之后目录不允许修改。配置的目录长度不超过64位，不允许出现中文路径。 |
| docker_path | 是 | Docker数据目录。 | 目录可自定义，仅支持自定义第一级目录，二级目录docker不允许修改，如果用户环境已安装Docker，则会将用户的docker配置“data-root”改为该目录。配置的目录长度不超过64位，不允许出现中文路径。 |
| service_group_id | 是 | Service用户组ID。 | service用户预置或已经存在时，填写service用户对应的gid，否则需未被使用。 |
| service_user_id | 是 | Service用户ID。 | service用户预置或已经存在时，填写service用户对应的uid，否则需未被使用 |

| gd_llm_no_think_model_url_key | 是 | 非思考型大模型接口url | 非思考型大模型接口的完整url，可以与思考型大模型接口url相同。 |

| gd_llm_auth_customize_json | 否 | 大模型接口鉴权自定义json | 如果使用自定义json鉴权，则在此处输入用于鉴权的json。例如：{"app_key": "123", "app_token": "xxaass123zzvv"}如果大模型接口没有鉴权相关的内容，可不传。不可以和gd_llm_auth_api_token同时使用。 |
| gd_llm_device_type | 是 | ModelService部署模型时使用的设备，npu或cpu。 | 使用npu部署模型则填npu，如果需要使用cpu部署模型，则需要填写cpu |
| gd_llm_device_path | 是 | �N腾Ascend单卡驱动目录，选择/dev/davinci[0-7] | 参照操作步骤，从/dev/davinci0到/dev/davinci07选择一个空闲的卡进行部署 |

| gd_llm_no_think_model_name | 是 | 非思考型大模型接口背后使用的模型的名称。 | 填写mindie部署配置项中的model_name，用于调用mindie提供的大模型接口。必须验证填写正确，否则调用大模型接口会失败。 |
| gd_llm_max_gen_token | 是 | 大模型接口生成的最大token数。 | 参考大模型接口服务在启动时设定的最大生成数，推荐与其保持一致。 |

## 物理机网络延迟

**ping**物理机，根据响应“time”判断网络延时，一般延时小于1ms为正常。
#### 处理步骤
****
- ping物理机的IP地址，约5-10分钟后查看返回“time”和丢包率。
  - 检查packet loss：为0%表示未丢包；不为0%表示有丢包，丢包率不能大于2%。
  - 检查rtt min/avg/max/mdev：值越大表示网络延迟越高。
****  - 联系物理机维护人员检查，服务器运行是否正常，对外ping其他服务器是否正常。
  - 服务器维护人员告知正常，即可联系网络维护人员排查网络问题，是否出现冗余线路有中断，或者网络出现拥塞，或其他未知问题。

## 容器异常退出后手动执行start命令不能正常启动

#### 现象描述
GaussDB AI助手物理机节点容器状态为Exited，且手动执行**docker start ***{**容器ID}*不能正常启动。
#### 可能原因
容器异常退出，导致该容器的运行目录仍存在，执行start命令时，docker发现存在该目录，不能正常启动。
#### 定位思路
手动执行以下命令，报错内容如下。
**docker start ***{**容器ID}*
#### **处理步骤**
- 以root用户登录GaussDB AI助手物理机节点。
****
- 执行以下命令，进入到容器运行时的文件目录。cd /run/docker/runtime-runc/moby/
******
- 找到以异常容器ID开头的目录，并执行以下命令删除该目录。rm -r {以异常容器ID开头的目录} 命令执行过程中请根据提示输入“y”或“yes”。
******
- 执行以下命令，尝试手动拉起容器。docker start {容器ID}
****
  - 若该容器状态为UP，则处理完成。
******
  - 若容器仍无法启动，执行以下命令，查看容器运行日志。docker logs {容器ID} 若日志中打印物理机性能相关问题，则根据提示进行相应排查。排查处理后再次重启容器。
- 若以上步骤仍不能解决问题，请联系技术支持处理。

## 故障处理原则

  - 以尽快恢复业务为原则。
  - 定位故障时，应及时采集故障数据信息，并尽量将采集到的故障数据信息保存在移动存储介质中或其它计算机中。
  - 在确定故障处理的方案时，应先评估影响，优先保证业务的正常使用。
  - 第三方的硬件故障，可查看第三方的相关资料或拨打第三方公司的服务电话。
  - 如果无法定位出故障点或无法按手册解决故障，及时联系技术支持，减少业务中断时间。
  - 严格遵守操作规程和行业安全规程，确保人身安全与设备安全。
  - 应先分析故障现象，定位原因后再进行处理。在原因不明的情况下应避免盲目操作，导致问题扩大化。
  - 在处理故障前，需要保留好故障现场的任何记录，不能随意删除数据或日志。
  - 在处理故障时，为了确保客户网络的安全和隐私，如果需要采集相关故障日志，请事先得到客户的同意和授权。
  - 在进行任何修改前，应先通过脚本导出、手工备份等方式备份数据。
  - 更换和维护设备部件过程中，要做好防静电措施，佩戴防静电腕带。
  - 在维护过程中遇到的任何问题，应详细记录各种原始信息。
  - 所有的重大操作，如重启进程均应作记录，并在操作前仔细确认操作的可行性，在做好相应的备份、应急和安全措施后，方可由有资格的操作人员执行。
  - 在系统恢复后，必须对运行情况进行观察，确认故障已经排除并及时填写相关的处理报告。
  - 慎重使用高危操作及命令。
  - 具备网络设备、操作系统和数据库基础知识，掌握其常用的操作命令，并能熟练使用它们开展维护工作。
  - 熟知GaussDB AI助手的逻辑结构、云数据库GaussDB AI助手各部件和现场设备的对应关系以及现场设备之间的物理连接关系。
  - 熟悉GaussDB AI助手业务流程、系统结构，能熟练操作业务相关的部件。
  - 了解基本故障相关定位和处理方法。
  - 掌握远程接入方式的使用。

## 认证鉴权

调用接口需进行Token认证鉴权。
Token在计算机系统中代表令牌（临时）的意思，拥有Token就代表拥有某种权限。Token认证就是在调用API的时候将Token加到请求消息头，从而通过身份认证，获得操作API的权限。
获取Token后，再调用其他接口时，您需要在请求消息头中添加“X-Mini-Token”，其值即为Token。例如Token值为“ABCDEFG....”，则调用接口时将“X-Mini-Token: ABCDEFG....”加到请求消息头即可，如下所示。
****
```
POST https://{{Endpoint}}/v1/interface
Content-Type: application/json
X-Mini-Token: ABCDEFG....
```

## 用户组管理概述

GaussDB AI助手平台提供用户组管理能力，旨在通过群组机制实现集群资源的便捷共享与协同运维。用户可通过创建用户组，安全、受控地将已纳管集群的操作权限共享给团队其他成员。
#### 角色与权限说明
用户组实行三层角色架构，各角色具体权限明细如下：
  - 角色定位：用户组的创建者，拥有该组的全局最高控制权。
    - 群组运维：拥有删除当前用户组的权限。
    - 成员管理：可添加或移除组成员，分配或收回“组内管理员”角色。
    - 资源共享：可决定并配置将自身名下已纳管的集群共享至当前用户组。
  - 角色定位：由组主或现有管理员委派的协同管理人员。
    - 成员管理：可管理除组主以外的组成员（包括添加/移除成员、设置其他成员角色）。
    - 资源共享：具备与组主同等的集群共享控制权，可将组主名下的已纳管集群共享给全组可见。
  - 角色定位：受邀加入用户组的基础协同人员。
    - 集群操作：无群组管理和资源分配权限。仅限在“集群管理 > 共享集群”模块下，对已共享的集群执行指定的运维操作（包含：历史告警查看、智能诊断）。
#### 个人组机制与资源视图界定
在用户组协同架构之外，系统基础机制与集群展示规则如下：
- 个人组机制：系统默认每个用户均拥有且归属于自己的专属“个人组”。
  - 个人视图 (集群管理 > 实例列表)：仅展示用户自身独立纳管的集群实例。
  - 协作视图 (集群管理 > 共享集群)：汇总展示用户加入各类用户组后，由组主或管理员开放共享的集群资源。

## 故障处理流程

故障处理总体流程分为四个过程：信息收集、判断、定位和排除。
- 处理重大故障前，请先联系技术支持，技术支持会协助您处理故障。
- 在故障处理过程中，维护人员可能需要执行修改配置数据、重启虚拟机等重大操作，为确保数据安全，应该提前保存现场数据，备份相关数据库、告警信息和日志文件等。
#### 故障信息收集
故障信息是故障处理的重要依据，系统维护人员应尽可能多地收集故障信息。
#### 故障判断
为方便用户使用，本手册完全基于故障现象进行分类，主要类型如下：
- 操作系统故障：微服务所在的物理机连接失败，响应慢。
- 网络故障：关键服务之间网络无法互通、网络中断、网络质量差。
  - gaussdb-doer-console服务故障：用户无法跳转到gaussdb-doer-consolee页面。
  - 模型服务故障：模型服务无响应、进程假死等。
#### 故障定位
故障定位就是从众多可能原因中找出故障原因的过程。通过一定方法或手段分析、比较各种可能的故障成因，不断排除非可能因素，最终确定故障发生的具体原因。
**关键服务故障定位**
此类故障的原因相对简单，同时会有服务日志、告警、错误提示和监控状态等信息。用户根据关键服务日志信息、告警处理建议、错误提示、进程重新启动等，一般就能定位故障。
#### 故障排除
定位故障原因后，需要进行故障排除。故障排除是指采取适当的措施或步骤清除故障、恢复系统的过程。如检查进程状态、查看日志、修改相关配置文件和重启服务等。
根据不同的故障按照不同的操作规程操作，进行故障排除。
#### 确认故障是否被排除
故障排除之后要注意进行检测，以确保故障彻底被排除。
通过查看日志、重复引发故障发生的动作和告警等方法确认系统已正常运行，并进行功能测试，以确保故障排除，业务正常。
#### 记录故障处理过程
故障排除后应回顾故障处理全过程，记录故障处理要点，给出针对此类故障的防范和改进措施，避免同类故障再次发生。

## 注册DBMind

#### 操作场景
DBMind提供了GaussDB集群的管理运维能力，在进行智能运维操作前，需要提前注册DBMind和集群。

#### 约束限制

#### 操作步骤

## 容器paused状态

#### 现象描述
GaussDB AI助手物理机节点容器状态为Paused状态。
#### 可能原因
手动执行了**docker pause ***{容器ID}*命令，把容器改为了暂停状态。
#### 定位思路
手动执行以下命令，查看容器状态为“Paused”。
**docker ps**
#### 处理步骤
- 以root用户登录GaussDB AI助手物理机节点。
****
- 执行以下命令，找到状态为“Paused”的容器ID。docker ps -a
******
- 执行以下命令，重新激活暂停的容器。docker unpause {容器ID}
****
  - 若该容器状态为UP且不包含(Paused)状态，则处理完成。
******
  - 若容器仍无法启动，执行以下命令，查看容器运行日志。docker logs {容器ID} 若日志中打印物理机性能相关问题，则根据提示进行相应排查。排查处理后再次激活容器。

## 构造请求

本节介绍REST API请求的组成，并以调用鉴权接口生成Token来说明如何调用API。该API获取的Token，Token可以用于调用其他API时鉴权。
#### 请求URI
请求URI由如下部分组成：
**{URI-scheme}://{Endpoint}/{resource-path}?{query-string}**
尽管请求URI包含在请求消息头中，但大多数语言或框架都要求您从请求消息中单独传递它，所以在此单独强调。
| 参数 | 描述 |
|---|---|
| URI-scheme | 表示用于传输请求的协议，当前所有API均采用HTTPS协议。 |
| Endpoint | 终端节点（Endpoint）为任意一台部署了GaussDB AI助手的节点的“IP:端口”，默认端口为8801。 |
| resource-path | 资源路径，即API访问路径。从具体API的URI模块获取，例如“生成Token”API的resource-path为“/v1/users/auth/mini-token”。 |
| query-string | 查询参数，是可选部分，并不是每个API都有查询参数。查询参数前面需要带一个“？”，形式为“参数名=参数取值”，例如“limit=10”，表示查询不超过10条数据。 |
#### 请求方法
HTTP请求方法（也称为操作或动词），它告诉服务你正在请求什么类型的操作。
| 方法 | 说明 |
|---|---|
| GET | 请求服务器返回指定资源。 |
| PUT | 请求服务器更新指定资源。 |
| POST | 请求服务器新增资源或执行特殊操作。 |
| DELETE | 请求服务器删除指定资源，如删除对象等。 |
在生成Token的URI部分，您可以看到其请求方法为“POST”，则其请求为：
```
POST https://{{Endpoint}}/v1/users/auth/mini-token
```
#### 请求消息头
附加请求头字段，如指定的URI和HTTP方法所要求的字段。例如定义消息体类型的请求头“Content-Type”，请求鉴权信息等。
详细的公共请求消息头字段请参见下表。
| 名称 | 描述 | 是否必选 | 示例 |
|---|---|---|---|
| Host | 请求的服务器信息，从服务API的URL中获取。值为hostname[:port]。端口缺省时使用默认的端口，https的默认端口为443。 | 否 | code.test.com or code.test.com:443 |
| Content-Type | 发送的实体的MIME类型。推荐用户默认使用application/json，如果API是对象、镜像上传等接口，媒体类型可按照流类型的不同进行确定。 | 是 | application/json |
| Content-Length | 请求body长度，单位为Byte。 | 否 | 3495 |
| X-Mini-Token | 用户Token。 用户Token也就是调用生成Token接口的响应值，该接口是唯一不需要认证的接口。 请求响应成功后在响应消息头中包含的“X-Mini-Token”的值即为Token值。 | 否 使用Token认证时该字段必选 | Token示例片段： MIIPAgYJKoZIhvcNAQcCo...ggg1BBIINPXsidG9rZ |
对于生成Token接口，由于不需要认证，所以只添加“Content-Type”即可，添加消息头后的请求如下所示。
```
POST https://{{Endpoint}}/v1/users/auth/mini-token
Content-Type: application/json
```
#### 请求消息体（可选）
该部分可选。请求消息体通常以结构化格式（如JSON或XML）发出，与请求消息头中Content-Type对应，传递除请求消息头之外的内容。若请求消息体中的参数支持中文，则中文字符必须为UTF-8编码。
每个接口的请求消息体内容不同，也并不是每个接口都需要有请求消息体（或者说消息体为空），GET、DELETE操作类型的接口就不需要消息体，消息体具体内容需要根据具体接口而定。
对于生成Token接口，您可以从接口的请求部分看到所需的请求参数及参数说明。将消息体加入后的请求如下所示，加粗的斜体字段需要根据实际值填写，其中***username***为用户名，***password***为用户登录密码。
```
POST https://{{Endpoint}}/v1/users/auth/mini-token
{
       "username" : "test",
       "password": "***"
}
```
到这里为止这个请求需要的内容就具备齐全了，您可以使用curl、Postman或直接编写代码等方式发送请求调用API。对于生成Token接口，返回的响应消息头中“X-Mini-Token”就是需要获取的Token。有了Token之后，您就可以使用Token认证调用其他API。

## 实时告警管理

#### 操作场景
GaussDB AI助手可以展示实时告警数据。当系统出现指标异常或出现异常事件后，GaussDB AI助手会将异常信息上报，展示在告警统计页面，用户可以根据具体告警信息定位问题。
#### 告警级别
- 紧急告警：该级别的故障影响到系统提供的服务，需要立即采取相应动作。如某设备或资源完全不可用，需立即采取措施，进行恢复。
- 重要告警：该级别的故障影响到服务质量，需要采取相应动作。如某设备或资源服务质量下降，需对其进行还原，恢复全部能力。
- 次要告警：该级别的故障还未影响到服务质量，但为了避免更严重的故障，需要在适当时间进行处理或进一步观察。
- 提示信息：该级别的故障指示会有潜在的错误影响到提供的服务，需要根据不同的错误进行处理。
#### 操作步骤
- 登录GaussDB AI助手。
  - 系统告警数量统计：按照紧急告警、重要告警、次要告警、提示信息四个告警级别统计系统告警数量。
    - 单击“操作 > 清除告警”，可清除的告警。
    - 单击，可实时手动刷新告警。

## 集群智能诊断

#### 操作场景
使用智能运维功能之前必须先注册集群，智能运维是针对已注册集群进行相关运维操作。
#### 约束限制
集群诊断之前必须先注册集群。
#### 操作步骤
- 登录GaussDB AI助手。
- 单击左侧“集群管理”。
- 在集群列表中，选择要诊断的集群，单击“智能诊断”按钮。
- 选择扫描出的异常，单击“一键诊断”进行诊断。
- 诊断结果会保存在“历史告警”中，单击“历史告警”即可查看。
- 在历史告警对话框中，单击“详情”，可获取实例诊断报告
